# juicy_plugins

Community plugin repository for JuicyPlayer. Each `plugins/<id>/` directory is one standalone plugin; CI automatically builds and publishes zips to GitHub Releases. The player fetches `registry.json` from this repo's root to list installable plugins — once downloaded and unpacked, they appear automatically in the player's Tools menu.

## Plugin Contract

A plugin = a `plugins/<id>/` directory containing at least:

```
plugins/<id>/
├─ plugin.json     # manifest (required)
├─ src/ ...        # frontend source (built by CI if package.json exists)
└─ server/         # optional: node backend
```

`plugin.json` schema:

```json
{
  "id": "my-plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "description": "One-line description",
  "entry": "dist/index.html",
  "window": { "width": 1280, "height": 800 },
  "backend": { "type": "node", "entry": "server/server.mjs" }
}
```

- `id` must match the directory name; ASCII letters / digits / hyphens only
- `version` follows semver — bump it to release an upgrade
- `window` is optional: the initial `width`/`height` of the plugin window (320–3840 × 240–2160); **when omitted, the window opens at the same size as the player's main window**. AI-generated tools (no plugin.json) default to 1100×720
- `backend` is optional, see "Node backend" below

**How the host recognizes plugins**: after a plugin zip is unpacked to `%APPDATA%/JuicyPlayer/tools/<id>/`, it is auto-scanned and shows up in the Tools popup as long as `dist/index.html` exists (`plugin.json` supplies the display name and description).

**Zip layout**: the zip root is the plugin root (`plugin.json`, `dist/`, `server/` at the zip root), generated by `scripts/pack.mjs` so the host can unpack in one step.

**Node backend**: the declared `backend.entry` is launched by the host with its built-in Node (`node server/server.mjs --port <free port>`, bound to 127.0.0.1 only). When ready, the backend prints one line `READY <port>` to stdout, and the host injects the port into the page as `window.__JUICY_API_PORT__`. Use this for plugins that need a local API (cross-origin proxies, encryption relays, etc.). The host **does not accept arbitrary command lines** — only node plus a relative entry inside the plugin directory. Reference implementation: `plugins/lyric-workshop/server/server.mjs`.

**UI language**: handled entirely by the plugin frontend. Convention (see `lyric-workshop`): default to Chinese or English based on the browser language, with an in-app toggle button persisted via `localStorage`.

## Third-Party Contributions

1. Fork this repo and add a `plugins/<your-plugin>/` directory (mirror the structure of `lyric-workshop`)
2. Verify locally: `node scripts/build-all.mjs <your-plugin-id>` (installs dependencies → builds → self-tests → packs the zip)
3. Open a PR — CI builds and validates automatically; after merge, the zip is published to a Release and `registry.json` is updated

Requirements:

- Valid `plugin.json` with `id` matching the directory name; `version` follows semver
- Self-contained build output (runs without `npm install` after build)
- No obfuscated code, remote script injection, or collecting/uploading user data

## Local Commands (repo root)

```bash
node scripts/build-all.mjs            # all plugins: install + build + self-test + pack
node scripts/build-all.mjs <id>       # build a single plugin
node scripts/pack.mjs <id>            # pack only (requires a built dist/)
node scripts/build-registry.mjs       # rebuild registry.json from packed artifacts
```

To develop a single plugin: go into `plugins/<id>/` and run `npm run dev` (Vite dev server, sharing the same backend business code as the plugin build).

## Interacting with Host Data

There are three channels between a plugin page and the JuicyPlayer host: the native bridge + resource provider (read/write local data), the node backend (local proxy / encryption relay), and the player's always-on HTTP API (library / playback / queue / lyrics / DSP at `http://127.0.0.1:8080/api/v1`, CORS fully open). Full reference: [docs/player-api.md](docs/player-api.md).
